## 责任划分

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 网关与业务框架 | 身份透传、课程、搜索、交易与学习基础业务 | 保留天机学堂模块与领域对象，作为演示载体 |
| Agent 入口 | RouteAgent 输出路由决策，SkillRegistry 选择行为与权限 | 低置信度或无效决策返回澄清，不盲目调用工具 |
| 受控能力层 | Capability 描述契约；AgentRuntime 校验权限、预算、取消与时限 | 工具只从当前 Skill 授权目录解析 |
| 多步编排层 | Planner 提案、Validator 确定性校验、Executor 绑定字段和分批调度 | 模型不能绕过校验直接执行方法；PLAN 只开放可规划只读能力 |
| 证据与终答 | 汇总脱敏结果和可信来源，评估目标、生成并校验最终引用 | 不把内部计划或模型原始推理作为对外进度发出 |
| 知识与记忆 | 文档双索引、混合召回、正式原文、会话摘要与明确偏好 | 记忆为低信任参考，不提升权限，也不等同于知识引用 |

## 三条核心链路

1. **DIRECT：** 入口路由 → 业务智能体 → Advisor / ToolCallback → Runtime → RAG、本地工具或 MCP → 流式回答与正式历史。
2. **PLAN：** 路由 → 只读能力规划 → 结构、权限、依赖与字段校验 → 最多四个就绪步骤组成的批次 → Runtime → 证据充分性评估 → 必要时有限重规划 → 基于证据的终答与引用校验。
3. **知识准备：** 上传原文 → OSS → 数据库文档与任务 → 提交后投递 MQ → 解析、清洗、切块 → 先 ES 后 Embedding/Redis → 成功状态；失败尝试清理本轮分块并按策略重试。

## 关键取舍

- 业务模型负责提案与语义判断，权限、输入绑定、依赖、次数与时间边界由 Java 代码落实。
- 业务 output 供下游字段绑定；脱敏 EvidenceSnapshot 供评估和终答。两者不互相替代。
- 召回单路失败或精排故障允许按既定策略降级；资料不足则说明边界，不编造来源。
- 运行取消会传播到本地 Future，但不能承诺远端模型或 HTTP 服务立即停止。
- 增强记忆通过 generation、版本比较和 forgottenAt，约束清除后的迟到任务写回。
